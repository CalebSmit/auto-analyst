## Intent

The authorization-code flow, finished on this machine. A refresh token is a secret at rest, so it is encrypted under a key derived from the one already in .env and written where the repo cannot commit it. Three states that are genuinely different and must read differently: nobody has ever signed in, somebody did and the token no longer works, and connected. The last of those is a thing a person fixes rather than a fault a run can retry, and the words have to say so.

## Tasks

- [x] An encrypted token store, in a place .gitignore already covers
- [x] authorize_url and the code exchange, with a state parameter that is checked and used once
- [x] ports/storage/sharefile.py reads and writes through the store, and rotates what ShareFile rotates
- [x] never authenticated, expired, and connected report as three different things
- [x] The sign-in button, its callback route, and the ShareFile half of the connection test

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A refresh token never appears in the repo, in a log, or in a repr
- A callback carrying a state nobody issued is refused, and a state is good once
- A rotated refresh token replaces the stored one rather than being dropped
- Never-signed-in and expired produce different reports, and neither reads as a fault a retry would fix
- No test in this phase can be read as evidence that real ShareFile answered
- ports.contracts('storage') is empty, and delivery's box adapter is still a contract because nothing writes a deliverable there yet
