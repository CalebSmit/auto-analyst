## Intent

A retry, a crash resume and a manual re-run after a fix are the same operation - and only the steps whose inputs actually changed are paid for twice.

## Blueprint nodes this phase implements

`step_executor` `idempotency_ledger` `checkpoint_store` 

## Tasks

- [x] step_key = sha256(step_id, input content hashes, skill@version, model_pin, context_ref, output_schema_version)
- [x] The idempotency ledger, written inside the same transaction as the step result
- [x] Execute at the frontier: completed steps satisfied from the ledger
- [x] Per-step timeout, one transport retry, then quarantine
- [x] A blocked run checkpoints and exits - no process, no lock, no context window held

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Killing a run mid-flight and resuming re-executes zero completed steps
- A late result from a timed-out step cannot overwrite the retry that replaced it
- A run blocked on a review item releases its lock and stops the wall-clock budget
- Steps pass content-addressed refs, never values
