## Intent

Every run ends with a computed verdict against versioned criteria, so no run's outcome is a matter of opinion.

## Blueprint nodes this phase implements

`ops_console` `run_scorecard` `analytics` `drift_monitor` `stall_alert` `cost_meter` 

## Tasks

- [x] FastAPI plus SSE over the event bus
- [x] The run scorecard: coverage, provenance, tie-out, conflicts, masking, numeric integrity, budget, review outstanding, deliverable QC
- [x] Versioned acceptance criteria, so 'what counted as working' is answerable for a run six months old
- [x] Drift monitor over override rate, confidence distribution and guard failure rate
- [x] Stall detection against the review SLA
- [x] Criteria versioned as data under ops/criteria/, pinned by ops/scorecard.py, never edited in place
- [x] Skill summaries on skill.completed for the scorecard: periods and reported gaps from timing-normalization

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every run gets a scorecard with a computed verdict
- The console replays a completed run from the event stream alone
- A stalled review item raises an alert against its SLA
- Node state comes from explicit events, never inferred from a log line's severity
