# P26 - Orchestrator agent and triage

**Block.** Block G - Scale, judgment and handoff  
**Gate.** `human` - tests passing is necessary but not sufficient; a human signs off.

## Intent

The model proposes a plan; it is still compiled, asserted and hashed before anything runs. This arrives last on purpose.

## Blueprint nodes this phase implements

`orchestrator` `triage` `run_plan` 

## Tasks

- [ ] Orchestrator working from the skill index (name and description only) and the job manifest
- [ ] Structured output: a plan proposal, never a value
- [ ] The proposal goes through the same compiler and the same plan assertions as a recipe
- [ ] Triage for no confident match, with a schema containing no field for a figure
- [ ] Fall back to the named recipe when the proposal fails assertions

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A proposed plan that violates any plan assertion is rejected and the recipe is used instead
- The orchestrator's context never contains a skill body, only the index
- A proposal is reproducible: same inputs, same plan_hash
- Triage can escalate but has no schema field in which a number could be recorded

## What needs a person

You confirm the plans the orchestrator proposes on real engagements are the plans you would have chosen, across at least ten runs.

    python tools/gate.py close P26 --signoff "name: what you checked"

## Note
