# P12 - Privacy: mask, vault, unmask, verify

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Block C - The harness around one step  
**Gate.** `auto` - closes on green tests alone.

## Intent

Tokens stable per engagement, re-identification deterministic, and no model node anywhere near the vault. The value here is cross-client isolation and precedent portability, not provider trust.

## Blueprint nodes this phase implements

`mask_engine` `mask_vault` `unmask_engine` `unmask_verify` 

## Tasks

- [ ] Masker over account names and identifying strings
- [ ] Per-engagement vault with a retention field, the only store that can re-identify anything
- [ ] Deterministic unmask in Python - no model has an unmask tool
- [ ] Unmask integrity check as a separate node from the masker, so the check can be tested independently of the thing it checks

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- The same account masks to the same token across runs weeks apart - period alignment depends on this
- A token issued under a different engagement_id fails the integrity check
- Zero residual mask tokens in any released artifact
- A graph assertion proves no llm-exec node reaches the vault
