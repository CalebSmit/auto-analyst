# P57 - Approving a recipe on a machine that has none

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** The consoles  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-17

## Intent

A registration records that somebody approved a workflow, which is why the file is not committed and why the admin console refuses to write it - a button that skipped the board would be the shortcut P33 exists to close. But refusing to do it badly is not the same as making it possible, and today it is impossible: there is no route, no button and no command. This adds the approval a person performs, through the board, under their own name, on the same four layers methodology clearance already uses.

## Tasks

- [x] An approval route beside the methodology clearance, calling the board rather than the register
- [x] The Setup page offers it where it already says a recipe is not approved
- [x] A recipe edited after approval loses it, and the route says so rather than silently re-approving

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A recipe can be approved from /admin on a clean clone, the approver's name is on the governance chain, and preflight check 10 goes green as a result
- The route refuses anything that is not an approval, the way board.register_recipe already does
- Nothing writes recipes/registered.yaml except the board, proved by a test that fails if a second writer appears
