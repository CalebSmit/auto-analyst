## Intent

Mark the part that does not vary, and let the run say what that was worth. The system prompt is the unit because it is stable by construction - a skill body and the references that skill declares - rather than stable by luck. What matters as much as the saving is that it is measurable: the manifest already has the fields, so a person can see the hit rate rather than be told caching is on. A miss must cost nothing but the write, and a call that cannot be cached must still be a call.

## Tasks

- [x] The system prompt carries a cache breakpoint, and the request says so rather than the adapter deciding
- [x] The run reports what was read from cache and what was written to it
- [x] A request that opts out is still a correct request

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- The system prompt is sent as a cacheable block and the payload is not
- Cache usage reaches the cost meter and the manifest, which already price it
- What is cacheable is stable by construction: two calls of one skill in one scope share a prefix byte for byte
- Nothing about the content sent to the model changes - only the marker on it
