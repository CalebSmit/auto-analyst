# P16 - Intake: roster, sweep, binding, lock, window

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Block D - First real vertical, local end to end  
**Gate.** `auto` - closes on green tests alone.

## Intent

What gets looked at, when a run actually starts, and the guarantee that an inactive engagement is unreachable rather than merely unchecked.

## Blueprint nodes this phase implements

`project_roster` `sweep_planner` `local_intake` `engagement_bind` `engagement_lock` `intake_window` `file_fingerprint` `config_store` 

## Tasks

- [ ] The roster and its three states: active, paused, archived
- [ ] Sweep planner reading the roster - the only thing that decides what is swept
- [ ] Pattern watches (one row, forty clients) and bound watches, with unmatched folders routed to a person and never guessed
- [ ] Fingerprinting, sha256 source_id, and source_version on re-upload
- [ ] Engagement binding that fails closed before anything is read, and the per-engagement lock
- [ ] Intake window: quiet_period 30 min, required_types from the recipe, max_wait 24 h

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Invariant 24 proven by graph walk: no path from any intake source into the pipeline for an off-roster engagement
- Six files arriving over ten minutes produce one run, not six
- A re-uploaded file becomes source_version 2 and supersedes the earlier run without overwriting its manifest
- Two runs launched on one engagement in the same second serialise on the lock
