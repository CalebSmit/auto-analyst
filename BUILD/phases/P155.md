# P155 - A scan is a layout too

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Reading what a client actually sends  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-10-03

## Intent

An engine returns a box with every fragment it reads, and a row is a band of the page - which is what P151 already built for a text layer. Carry the geometry through the OCR port and send a scanned page down the same band reader, so a scan and a text layer go on travelling the same road and no locator, guard or citation has to know which it was.

## Tasks

- [x] Give OCRLine a box, in page points, and say on OCRPage whether that unit is exact or estimated
- [x] Have the rapidocr and tesseract adapters divide their boxes by the render scale they chose, so the layout tolerances keep the meaning P151 calibrated
- [x] Make layout.py's word-level table reader public and call it from both paths, so there is one implementation of what a row is
- [x] Build the tables of a scanned page from its boxes, falling back to the line reader when an engine offers no geometry

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A scanned copy of the filing's page 56 yields the same two columns, the same Total assets of 521,728 and a balance sheet that states both sides
- The text-layer path is unchanged: the whole-filing counts P151 measured still hold
- A page an engine read with no boxes still reads through the line reader rather than raising
