## Intent

What a person reads off a dashboard is what the record says - the right colour for the verdict, a denominator under every claim, the decisions that were made, the model that made them, and no question asked about work that has been superseded.

## Tasks

- [x] The scorecard verdict is coloured from the verdicts the scorecard actually emits (pass, pass_with_exceptions, partial, blocked, halted), from one table shared with the run states
- [x] Empty states branch on whether there is a denominator: no run has reached a proposal is not the same sentence as every proposal was inside the bar
- [x] A decision trail: GET /api/runs/{id}/decisions, and a panel on the run detail saying who decided what, what was proposed, the reason, and whether the proposal was revealed before the decision
- [x] Open review items on a superseded run leave the inbox, and the run says what replaced it
- [x] The run detail carries the model pin, the steps with their attempts, spend against the budget ceiling, and the run manifest as a record rather than a deliverable
- [x] Resuming a quarantined run requires a reason, as halting one does
- [x] The composition root passes the console its blobs, queue and scope, and the sweep loop - not a browser - raises stall alerts and escalates overdue review items

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every verdict the scorecard can emit maps to a tone, and a passing run is not painted as needing attention
- No empty state claims a rate or an absence that has no denominator behind it
- A run's decisions are readable over HTTP and on the page, with the reveal recorded beside each
- An item on a superseded run is not offered for answering
- Alerts and SLA escalation happen with no browser open
