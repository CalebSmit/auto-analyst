## Intent

A person can see at a glance what needs them, answer a review in the order the review surface intends, and set up an engagement without editing JSON - and nothing the consoles do fails silently.

## Tasks

- [x] Activity: runs lead with the client, scope and age; states in the three meaning colours with the stop reason; the page opens on the run that needs attention; a review panel shows question, source and reasons, reveals the proposal on request and on the record, and records accept, correct, reject or escalate with a reason; halt and resume ask in the page; the trace can show only what a run touched
- [x] The live feed closes a finished run's stream and ignores repeats; refused actions are said, not swallowed
- [x] Setup: engagements lead with the client and say what a profile lacks; the profile is a form with the JSON one click away; workflow and methodology clearance ask in the page
- [x] Every page: an in-page dialog instead of browser pop-ups, a count of what waits on a person on the Activity tab and in the window title, links to a run, a review item and a profile, a tab icon
- [x] The console's run and review rows carry the client and scope from the roster, through the composition root

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- No page uses a browser pop-up, declares a name twice, or ships a script that does not parse
- A review item's proposal is shown only on request, and accepting or correcting is not offered before it
- A finished run's stream is closed rather than replayed, and a refused action is reported
- Runs and review items name the client, and an engagement names what its profile still lacks
