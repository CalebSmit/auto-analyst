# P65 - An acknowledgement is a decision, not a default

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** The interview  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-18

## Intent

The register's acknowledgement records that a person looked and found nobody. Its note is the content of that decision, and the code supplied one when the person did not. Re-recording replaced whatever was there without naming it. Both make a permanent record easy to destroy by accident, which is how this session destroyed one.

## Tasks

- [x] An acknowledgement with no words is refused rather than worded by the code
- [x] Re-recording an acknowledgement that is still current is refused, naming who made it and when
- [x] An unknown topic on mark says why, rather than raising into the session
- [x] Every CLI handler names the knowledge folder it works on, so the module attribute is the only source

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- register --none with no note refuses and records nothing
- An acknowledgement that is still current cannot be silently replaced, and the refusal names who made it and when
- An acknowledgement that has gone stale can still be renewed, because that is the legitimate act
- Every interview command refuses a bad argument with a sentence rather than a traceback
- No interview command reaches the real knowledge/ when the module's KNOWLEDGE has been pointed elsewhere
