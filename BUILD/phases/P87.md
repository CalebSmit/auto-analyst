## Intent

A storage adapter that really reads a Box folder, over client credentials with user impersonation, because a service identity without impersonation authenticates as nobody who can see his folders. Registered so AA_STORAGE_ADAPTER=box is a choice the system understands. It cannot be proved against a real tenant here, so the tests prove the logic against a replayed transport and say so in those words rather than reading as evidence the connection works.

## Tasks

- [x] ports/storage/box.py: list, read, stat, over client credentials with user impersonation
- [x] Stable order by path, sha256 computed rather than trusted, no cache outliving a sweep
- [x] Correct BOX_ENTERPRISE_ID to BOX_USER_ID in the delivery adapter, and record it as a finding
- [x] Declare the HTTP client this adapter uses rather than inheriting it from anthropic
- [x] A refused credential is a different diagnosis from a missing one

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- AA_STORAGE_ADAPTER=box builds a real adapter and passes the port conformance suite
- list returns files in path order and folders are not files
- stat computes a sha256 rather than trusting a hash the service offers
- The Box credentials named in the code are the ones that work: BOX_USER_ID with box_subject_type=user, not an enterprise id
- A credential the service refuses diagnoses differently from one the environment never set
- No test in this phase can be read as evidence that a real Box tenant answered
- The surface snapshot records exactly two changes - the CREDENTIAL_REFUSED diagnosis and box on the storage port - and no others
