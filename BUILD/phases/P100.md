# P100 - The hundredth phase, and the comparison that broke on it

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Reading what a client actually sends  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-22

## Intent

Order phases and checkpoints by their number rather than by their spelling, everywhere the gate compares them. The gate is the only thing permitted to mark a phase done, so a gate that mis-orders phases is the one defect that can let every other defect through.

## Tasks

- [x] One ordering rule for a phase or checkpoint id, used everywhere the gate compares two
- [x] A checkpoint covers the phases up to its own, and never a phase added after it
- [x] Phases still close in order at three digits, so P100 cannot close while P99 is open
- [x] The phases past the last checkpoint are still reported, which is the check that caught this

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every comparison of two phase or checkpoint ids in the gate orders them by number
- A plan of a hundred and more phases reports coverage, ordering and what is owed correctly
- tests/p01 passes at three digits, and a test fails if a string comparison comes back
