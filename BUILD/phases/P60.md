# P60 - A quarantine that leaves something behind

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** The engine  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-18

## Intent

A run that quarantines tells nobody. The step is finished QUARANTINED, an event is emitted, and that is the whole of it: no quarantine record, no review item, nobody assigned, nothing in the queue. constraints.yaml says exhaustion always produces an artifact - a quarantine record or a review item - and the code that honours it sits behind a path nothing could reach. Beside it, on_failure has been rendered on every plan and read by nothing, so a step declaring 'halt' and a step declaring 'review' end the same way as one declaring neither.

## Tasks

- [x] Every quarantined step leaves exactly one quarantine record, from every ending
- [x] A step declaring on_failure review opens a review item so a person is told; one declaring quarantine does not
- [x] A step declaring on_failure halt ends the run, and the driver closes it out rather than the executor moving it to a terminal state
- [x] A transport exhaustion carries a diagnostic code like every other ending
- [x] A new diagnostic code for transport exhaustion, in the registry and in the blueprint's table

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- store.quarantines() is non-empty for every run with a quarantined step, and a resumed pass over the same step key does not write a second record
- on_failure review opens an item, quarantine opens none, and halt ends the pass with the run closed out halted and a manifest written
- The executor never moves a run into a terminal state
- Every quarantine event carries the code its failure arrived with, including transport exhaustion
