## Intent

Fixtures only cover cases somebody thought of. Replay answers the question fixtures cannot: would this candidate have changed anything real?

## Blueprint nodes this phase implements

`eval_harness` `replay_harness` 

## Tasks

- [x] Golden fixtures per skill plus the adversarial fixtures per guard
- [x] The per-skill acceptance gates from the blueprint's gate table
- [x] Replay: re-run a candidate over the masked inputs of past engagements and diff against what was delivered
- [x] gate eval <skill> as a first-class command
- [x] evals/gates.yaml as the named numeric form of the blueprint's gate table, with owed gates marked by the control that measures them
- [x] The dispatcher records inputs and proposal blobs per skill step; the Replay Harness restores a step from them

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every shipped skill has fixtures and a named numeric gate
- Replay produces a diff against past deliverables, not just a pass/fail
- A skill below its gate cannot be registered
- Fixture coverage is reported, including what is not covered
- A gate the offline harness cannot measure is reported as owed - on the scorecard, in coverage and on the registration record - never as passed
