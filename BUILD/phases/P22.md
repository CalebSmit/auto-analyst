# P22 - Eval and replay harnesses

**Block.** Block F - Assurance and operations  
**Gate.** `auto` - closes on green tests alone.

## Intent

Fixtures only cover cases somebody thought of. Replay answers the question fixtures cannot: would this candidate have changed anything real?

## Blueprint nodes this phase implements

`eval_harness` `replay_harness` 

## Tasks

- [ ] Golden fixtures per skill plus the adversarial fixtures per guard
- [ ] The per-skill acceptance gates from the blueprint's gate table
- [ ] Replay: re-run a candidate over the masked inputs of past engagements and diff against what was delivered
- [ ] gate eval <skill> as a first-class command

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every shipped skill has fixtures and a named numeric gate
- Replay produces a diff against past deliverables, not just a pass/fail
- A skill below its gate cannot be registered
- Fixture coverage is reported, including what is not covered

## Verify

```
python -m pytest tests/p22 -q
python tools/gate.py check P22
```
