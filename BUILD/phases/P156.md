# P156 - A file that will not open

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Reading what a client actually sends  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-10-03

## Intent

Say the same thing about a document that cannot be opened as about a workbook that cannot be opened - the file, named, and the fact that it is unreadable - rather than letting a library's exception out of the reader. One branch already does this and the other does not, which is one implementation short rather than a missing feature.

## Tasks

- [x] Catch what a document reader raises at the boundary and diagnose it as UNREADABLE_FILE, as the workbook branch already does
- [x] Keep NotText separate: a format this build does not read is a different answer from a file that will not open
- [x] Add a truncated document to the file rehearsal, so the ending is on the record rather than in a traceback

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A truncated PDF, a corrupt .docx and a truncated image each produce INTAKE.UNREADABLE_FILE naming the file, and none of them escapes as a library exception
- A file in a format this build routes but does not read still produces FORMAT_NOT_READ, because the thing to do about it is different
- The rehearsal ends a run on the record for a truncated file rather than failing the worker
