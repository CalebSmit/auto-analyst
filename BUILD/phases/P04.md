## Intent

The record. Every guard writes to it, passes included, so silence is never ambiguous - and the manifest is written unconditionally, including when a run halts.

## Blueprint nodes this phase implements

`event_bus` `run_store` `run_manifest` `checkpoint_store` 

## Tasks

- [x] SQLAlchemy models: run, step, event, artifact, review_item, decision
- [x] A repository port over the store, so SQLite and Postgres are one URL apart
- [x] Append-only event bus - no update path exists in the API at all
- [x] Manifest writer wired to run end regardless of outcome
- [x] The seven run states: queued, running, waiting, quarantined, halted, delivered, superseded

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A halted run still writes a complete manifest
- The event table has no update path reachable from application code
- All seven run states are reachable and asserted in tests
- The store conformance suite is parameterised over SQLite and Postgres, passes on SQLite, and reports the Postgres run as not-run rather than skipping it silently when no server is reachable
