# P102 - Asking the model whether it is there

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** A run that finishes  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-22

## Intent

Let a person find out from the dashboard whether the model door opens, what it costs and which model answers, before any client work depends on it. The same shape as the Box and ShareFile tests, because 'connection failed' is not an answer and the value of the button is knowing which of three screens to open.

## Tasks

- [x] A probe that walks the model door in order - adapter, key, a real call, and what it was charged - reporting each step on its own
- [x] The smallest possible real call, with the cost of the test itself reported, since this is the one connection test that spends money
- [x] A step after a failure reads 'not reached', never 'fail', so nobody is sent to the wrong screen
- [x] Say which concrete model answered, because the tier is a per-skill decision and 'mid' is not an answer to 'which AI is this using'

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Pressing the button on a machine with no key says the key is missing, and names it, without making a call
- Pressing it with a working key reports the model that answered and what the test cost
- A refusal from the API is reported as the step that failed, with the provider's own reason, and the steps after it as not reached
- The probe cannot be reached by a run, and spends nothing unless a person pressed it
