# P107 - Ready to run has to mean it

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** A run that finishes  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-22

## Intent

Make the setup checklist cover the two prerequisites that live outside the configuration, so that finishing it means a run would actually do something. A checklist that reports done on a machine that cannot mask is worse than no checklist: it is the one screen a first-time reader trusts.

## Tasks

- [x] The setup payload says whether the vault opens and whether the model door reaches a provider
- [x] Both appear as steps in the checklist, each with the one thing to do about it
- [x] The vault key is validated rather than merely counted - a malformed key is not a key
- [x] Ready to run appears only when a run would mask, call a model and write something

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A machine with no vault key is told so by the checklist, before it activates an engagement
- A machine answering from fixtures is told that no work will be done, and how to change it
- A key that is present and malformed reads as missing rather than as done
- With both satisfied and every other step done, the page says ready and means it
