# P99 - The totals that re-add, and the rows they cover

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Block.** Reading what a client actually sends  
**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-22

## Intent

Find, deterministically and with no model, which totals in a parsed statement re-add from which rows - and report what does not, rather than guessing at it. A total that foots is arithmetic evidence about every row under it, which is the difference between an analyst reading 2,198 figures and reading the 288 nothing covers.

## Tasks

- [x] A reader that finds, for each total, the contiguous run of rows above it that sums to it - the lines, or the subtotals
- [x] Report a total that re-adds from nothing as uncovered, never as covered by the nearest thing that nearly fits
- [x] Carry the result on the read report and into the record a person sees, so a statement that does not foot is visible the day it arrives
- [x] Say plainly what this is not: arithmetic proves addition and not selection, and a wrong row added correctly still foots

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- Every subtotal in the real client's statements is found with the rows it re-adds from, and the count of covered rows is asserted
- A statement with a total that does not re-add reports that total as uncovered and says by how much
- Nothing here reaches a model, an OCR engine or the network
- The result reaches a person through the read record rather than sitting on a dataclass nobody looks at
