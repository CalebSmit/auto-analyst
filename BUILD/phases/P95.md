# P95 - The tracker reads the folder and updates itself

*Generated from BUILD/plan.json by `gate render`. Change it with `gate amend`.*

**Gate.** `auto` - closes on green tests alone.
  
**Closed.** 2026-09-21

## Intent

Point it at a folder, get a tracker. Each file classified from what can be read cheaply, matched to an item by reference or by kind, and written into a workbook a person opens - with what a person already wrote in it left alone. An update that overwrote somebody's notes or their Not Applicable marks would be worse than no update, because they would have to be re-entered every time and would stop being entered.

## Tasks

- [x] Read a folder through the storage port and classify what is in it
- [x] Write the tracker as a workbook: one row an item, with status, how it was matched, and the evidence
- [x] Re-writing preserves what a person put in it - notes, In Model?, Not Applicable
- [x] Say which files answered nothing, because those are the ones somebody has to look at
- [x] A button on /admin: point it at a folder and a tracker, and press it

## Exit criteria

*The phase closes when all of these are true and `gate close` says so.*

- A folder of ordinary filenames produces a tracker with the right items marked provided
- A second run over the same folder changes nothing a person wrote
- A file that matched no item is reported rather than dropped
- An inferred match is visible in the workbook, not only in the code
- The tracker is reached by something a person can press, and is not on the unreachable list
